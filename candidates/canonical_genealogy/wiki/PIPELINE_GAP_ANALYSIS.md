Pav's question, verbatim: **"what is the current build shape now and what shape does
it need to be to scale towards that"** -- where *that* is the agent-driven
review-and-update smart viewer pipeline.

Short answer. Today the build is a set of excellent hand-finished single-file
instruments with a human-grade review tool bolted alongside: pins exist, but a pin is
a flat record with no status, no edit, no exact replay, and a screenshot that misses
the DOM. The target is the same instruments on a conveyor: a pin is a machine-readable
ticket that carries its own exact viewer slice; agents triage it (wiki-armed, through
the framework lens), scouts fetch what is missing, a patch agent edits under written
law, a scripted gate verifies the change against the pin's own frame, and the pin
closes with a recorded give that Pav verifies in-frame. Nearly everything required is
additive -- two window hooks, a few server routes, one check script, one manifest.
The deep structure (single-file viewers, append-only substrate, honesty gates) is
already the right shape and is explicitly on the keep list.

Companion docs in this wiki: `PIPELINE.md` (the one-page conveyor, added at
finalize), `UI_GUIDELINES.md` (the law patches must obey),
`REVIEW_THROUGH_THE_FRAMEWORK.md` (the lens triage uses), and the five scouted pages
(`viewer-app.md`, `data-layer.md`, `substrate.md`, `review-tool.md`, `toys-specs.md`)
which are the agents' map of the codebase.

## 2. Target shape: the conveyor

One pin rides the belt end to end:

```
PIN (ask + exact slice)                          reviewer drops it in the viewer
  -> TRIAGE agent                                wiki-armed, framework-POV
       classifies the forcing event (pull/squeeze), scopes vs the frozen list,
       names the wiki pages + scout requests, emits a patch brief
  -> SCOUTS                                      ingest required data, citations only
  -> PATCH agent                                 UI-guidelines-bound surgical edits,
       embeds regenerated via the named commands, honesty gates intact
  -> VERIFICATION GATE (one command)             node --check  +  headless #lint
       + state-replay smoke (applyReviewState roundtrip)
       + screenshot diff against the pin's own frame
  -> GIVE recorded on the pin                    status transition appended,
       give text + commit ref
  -> PAV verifies in-frame                       go-to-frame, old PNG vs new build,
       flips applied -> verified (or re-opens)
```

Artifact contracts between stations: the **pin record** is the ticket; the
**.review.json** is the exact slice; the **wiki** is the map; **UI_GUIDELINES.md** is
the law; the **manifest** is the dependency graph; the **gate verdict** is the
evidence; the **pins ledger** (status trajectory) is the dated record.

Framework POV (used where it clarifies, never as decoration -- full mapping with
honest limits in `REVIEW_THROUGH_THE_FRAMEWORK.md`): a pin is a forcing event (D4)
from the Pav-observer on the viewer-wrapper; ask/give is the A-/A+ fold with the
A- side doing the compilation work; the status enum is a weld lifecycle where a
rejected ask is demoted-not-deleted; the ledger is the same dated-record discipline
the substrate already enforces.

### Agent roles and model tiers

| Role | Model tier | Bound by | Notes |
|---|---|---|---|
| Scout (data ingest, wiki refresh, harvests) | Claude Sonnet | substrate append-only rules; citations mandatory | cheap, parallel, read-heavy; never edits the viewer |
| Triage (pin -> ticket -> patch brief) | Claude Fable (Sonnet acceptable for purely cosmetic pins) | wiki + REVIEW_THROUGH_THE_FRAMEWORK + frozen list | judgment work; classifies, scopes, routes |
| Patch / synthesis (the actual edit) | Claude Fable | UI_GUIDELINES + wiki gotchas + manifest | surgical additive edits; regenerates embeds; runs the gate |
| Skeptic (adversarial review) | Claude Opus | the change diff + the pin | escalation only, on load-bearing changes -- not every pin |
| External pass | GPT-5.5 + Gemini | load-bearing claims only | the workflow's agent() is Claude-only, so cross-model is the real external A- |
| Verifier | Pav | the replayed frame | the **only** role that can set status=verified; agents cap at applied |

## 5. Keep list -- the shape that must NOT change

1. **Single-file, self-contained viewers.** This is a sharing feature, not debt: one
   file opens anywhere with no build step, no server, no dependencies. The conveyor
   serves and patches these files; it never splits them into bundles. (The harness and
   server stay outside the instruments.)
2. **Append-only substrate + dated records.** facts/verifications are never edited,
   only appended; revisions are newer facts; retractions are verification records.
   The pin status trajectory copies this discipline -- demote, never delete.
3. **The honesty gates.** Proxy disclosure in-legend, MODELLED/ESTIMATE tags traveling
   with values, contribution-share certainty caps, draw-nothing-when-data-absent,
   never a fabricated measured value. The gate automates *around* these, never through
   them; a screenshot diff PASS does not license removing a disclosure.
4. **The frozen set.** SCHEMA_v2.md, the 7 base specimens, viewer_v0/v1/v2,
   candidates/frame_lock_data. The manifest marks them frozen; agents route around
   via overlays and substrate.
5. **Toy-first cadence.** The git log shows the working rhythm: prove an interaction
   in a throwaway single-file toy, then graduate it into the viewer. The conveyor
   should make this cheaper, not bypass it.
6. **Inject-on-serve review chrome.** Viewer files stay clean; the overlay exists only
   through :8742. Plain serving (:8741) keeps a pristine instrument.
7. **Pav as the verified-setter.** Agents may move a pin to applied; only the human
   reviewer closes the loop in-frame. This is the pipeline's ground truth, kept by
   design.
8. **Tier-3 posture.** The convergence list stays 9. This pipeline ships viewer
   improvements and honest records of them -- it is not a promotion mechanism.

## 6. Honest limits

- **Scale means throughput, not platform.** This is a localhost, single-machine,
  one-reviewer pipeline. "Scale" here means more pins processed correctly by agents
  with less hand-holding -- not multi-tenant fantasy.
- **Screenshot diff is evidence, not proof.** DPR caps, font rasterization, and the
  quality ladder make pixel equality unattainable; the diff is thresholded,
  best-effort, and always paired with the replay smoke + lint assertions. Its verdict
  is disclosed as such on the pin.
- **foreignObject capture is best-effort.** Same-origin DOM rasterization can miss
  some CSS; capture failures must be disclosed on the pin record, never silently
  passed off as a complete frame.
- **The framework mapping is a lens.** Per REVIEW_THROUGH_THE_FRAMEWORK section 7:
  forcing-event-as-pin and dated-record discipline are structural transfers; the
  charge vocabulary is honest metaphor. No qualitative reading in this pipeline is
  ever rendered as a measured value.
- **No timeline promises.** Stages are ordered by dependency and size. Stage 1 is in
  flight this round; nothing else is dated.
