**(1) Prioritization**
Verdict: right order, but run a tiny instrument/range pilot first.

Single-runner V4 before multi-runner is justified because the plan’s multi-runner effort plumbing is already known-broken: Claude `output_tokens=6`, Gemini `null/0.0s` ([FRONTIER_PLAN.md](/D:/PlatformOperator/research/pav/candidates/canonical_genealogy/hyperspace_spec/FRONTIER_PLAN.md:15), [line 24](/D:/PlatformOperator/research/pav/candidates/canonical_genealogy/hyperspace_spec/FRONTIER_PLAN.md:24)). Spearman on ~25 targets is meaningful only for a big monotone effect, not a law. It is non-circular if difficulty labels are fixed before runs from independent sources such as MATH, GPQA, ARC/AIME-style exact-answer tasks ([MATH](https://arxiv.org/abs/2103.03874), [GPQA](https://arxiv.org/abs/2311.12022), [ARC](https://arxiv.org/abs/1911.01547)); it is circular if targets/labels are tuned after seeing GPT-5.5 effort. Over-claim: “effort IS difficulty” should be demoted to “GPT-5.5 reasoning effort correlates with pre-registered external difficulty under this harness.”

**(2) Predict-Half**
Verdict: sound as a calibration experiment; not sound as a “future camera” yet.

The seal/prior-cut design is basically right: plant from `C`, write `{C_hash,R,s,t_obs}` before reveal, then score ([line 41](/D:/PlatformOperator/research/pav/candidates/canonical_genealogy/hyperspace_spec/FRONTIER_PLAN.md:41)). Main fatal risks are leakage and weak calibration statistics. A local timestamp is not a strong seal; use append-only hashes/external timestamping and construct `C/T` blind. Reliability curves are informative, but the proposed ~12 trials is too small for bins; use Brier/log score, ECE, and resolution, not just diagonal eyeballing ([line 42](/D:/PlatformOperator/research/pav/candidates/canonical_genealogy/hyperspace_spec/FRONTIER_PLAN.md:42); calibration background: [Guo et al. 2017](https://arxiv.org/abs/1706.04599), proper scoring rules: [Gneiting/Raftery](https://doi.org/10.1198/016214506000001437)). Self-declared sharpness is elicitable, but only imperfectly; LMs can self-evaluate in some formats yet struggle OOD ([Kadavath et al.](https://arxiv.org/abs/2207.05221)). Over-claim: “honest forward camera” should be “calibrated sealed forecaster on this task class.”

**(3) Measurement Flaws**
Verdict: fixing Claude `output_tokens` is necessary, but thinking-trace length is only a proxy, not a clean fix.

Use true vendor-reported reasoning/billed tokens if available; otherwise report Claude separately or use within-provider budget curves. Raw thinking length is provider-policy-dependent and may measure verbosity/overthinking, not difficulty; longer reasoning can be non-monotonic with accuracy ([overthinking study](https://arxiv.org/abs/2507.04023)). Other flaws: wall-seconds for Claude/Gemini confounds latency with effort ([line 61](/D:/PlatformOperator/research/pav/candidates/canonical_genealogy/hyperspace_spec/FRONTIER_PLAN.md:61)); single-run results need repeats/seeds; public benchmark items risk contamination; canonicalizer gold labels via 2/3 LLM agreement are not human ground truth ([line 32](/D:/PlatformOperator/research/pav/candidates/canonical_genealogy/hyperspace_spec/FRONTIER_PLAN.md:32)); predict-half v0 is information-blindness, not wall-clock future ([line 44](/D:/PlatformOperator/research/pav/candidates/canonical_genealogy/hyperspace_spec/FRONTIER_PLAN.md:44)).
