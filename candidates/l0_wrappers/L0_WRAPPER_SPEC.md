## 1. What an L0 wrapper is (and is not)

The genealogy specimens render **one merge event** — a weld's whole life. Their parents, actors, sub-wrappers, descendants and rivals are *names inside one specimen's frame*. The L0 catalog is the **entity layer underneath**: one record per *thing* — any thing — frame-wrapped the same way the framework wraps everything else:

- a **certain kernel** fading into a **fuzzy membrane** (the certain-core → frontier discipline, here driven *directly by verification state* rather than authored confidence),
- rendered in the **observer global kernels** `{time, space, knowledge, meaning}`,
- carrying a **frame_layer** `{physical | latent | straddle}` with graded memberships (D3 vocabulary, reused),
- with **graded membership as the default** (D5 vocabulary, reused),
- and with the **semantic generic ↔ branded specific axis as first-class lineage** (§2.2) — the contextual-scale dial.

An L0 wrapper is **not** a specimen (no weld, no parents, no harvest groups — those stay in SCHEMA_v2), and the wrapper JSON is **not a second source of truth**: it is a **compiled view over substrate facts** (§2.9). If a field has no backing fact, the field is empty and the gap is visible. Empty is correct signal.

## 2. The wrapper record shape

One JSON object per entity, conforming to `wrapper.template.json`. Field groups:

### 2.0 Identity and kind

| Field | Type | Meaning |
|---|---|---|
| `wrapper_id` | string | `l0:<slug>` — kebab slug, stable, unique across the catalog. |
| `kind` | string | Core open vocabulary: `object \| device-model \| ai-model \| person \| compound \| book \| idea \| institution \| place \| work \| event`. Extending the vocabulary requires a PROPOSED entry in `SWEEP_LOG.md` *before* first use (the same propose-before-use discipline SCHEMA_v2 applies to new weld_type terms). |
| `names` | object | `{ canonical: string, aka: [string] }`. Each name backed by `fact_refs[]` where contested (aka entries for brand names, IUPAC names, codenames). |

### 2.1 Substrate facts for identity/lifecycle/level

All wrapper content is fed by facts in `facts/l0_catalog.entities.jsonl` with:
- `specimen: "l0-catalog"` (the catalog is a pseudo-specimen to the compiler — see §2.9 for the expected, honest validation flag),
- `subject_id: "<slug>"` (the wrapper's slug, exactly),
- `fact_id: "l0-<slug>-NNNN"` (entities file) — the disjoint namespace that keeps the compiler's HAZARD guard quiet (§7.3),
- everything else per `SUBSTRATE_SPEC.md` §2 unchanged (real source URL, `retrieved_at`, certainty rubric, `verification: "pending"` at emit).

### 2.2 ABSTRACTION — the contextual-scale dial on the semantic axis

The generic ↔ specific axis (smartphone → iPhone → iPhone 15 Pro) is **frame-relative identity on the semantic/abstraction axis** — the validated zoom-vs-reframe distinction (contextual frame-relativity, REAL, 2026-06-09): *zooming* shows more detail of the same identity; *dialing the abstraction ladder* is a **reframe** — the identity under discussion changes rung. Render it as a **ladder you dial along**, never as a zoom.

> **By analogy (honest caveat, per Opus review 2026-06-11):** the 2026-06-09 canon is specifically about *locality-of-nonlinearity* (range-framing a parent variable flips interactive↔additive in a model-merge). The generic↔specific abstraction ladder reuses the **same "reframe, not zoom" distinction by analogy** across a different mechanism (identity-rung selection vs. variable-range framing). It is a deliberate conceptual lift, not the identical phenomenon — flagged here so a future agent does not over-read it as the one canon.

```jsonc
"abstraction": {
  "level": "generic | class | instance",      // DERIVED default (see below), overridable per scope
  "ladder": {
    "generalizes_to":  "l0:<slug> | proposed:<slug> | null",   // one rung up
    "specializes_to": ["l0:<slug> | proposed:<slug>", ...]     // rungs down
  },
  "level_by_scope": { "<scope>": "generic|class|instance", ... },  // OPTIONAL, fact-backed only
  "fact_refs": ["l0-<slug>-rNNNN", ...]
}
```

- **Ladder edges are relations** (§2.7): `instance-of`, `subclass-of`, and `brand-of` facts in the relations file *are* the ladder; the `abstraction` block is compiled from them. No ladder edge without a backing fact.
- **`level` is derived** from ladder position by default (no out-edge up = `generic`; specialization edges both ways = `class`; `instance-of`/`brand-of` out-edge = `instance`), and **overridable by `abstraction_level` facts** where the record demands it.
- **The level can itself be frame-relative.** Canonical case: *aspirin* — generic in one jurisdiction (US genericide), a protected Bayer brand in others. Model this as **scope-suffixed predicates** (`abstraction_level:us`, `abstraction_level:de`), one fact each, each with its own source — NOT as a dispute. Two scoped levels are two frame-readings of one entity, not a contradiction; the compiler's `(specimen, subject, predicate)` grouping keeps them in separate resolution groups by construction. The abstraction dial then reads differently under different `space`-frame settings — the contextual-scale dial demonstrated *in the data*, in a second kind (§5, sample 5).

### 2.3 KERNEL — the certain core

```jsonc
"kernel": {
  "facts": [ { "fact_id", "predicate", "value", "battle_count" } ],   // compiled, see admission rule
  "statement": ""        // optional one-line prose digest of what the kernel facts jointly say
}
```

**Kernel admission rule (strict, mechanical):** a fact enters the kernel iff, in the current compile,
1. its verification **bucket = `corroborated`** (battle-tested against at least one independent route), AND
2. its `certainty >= 0.7` (aggregator-attested band), AND
3. its `notes` carry **no** `ESTIMATE:`/`PROXY:` tag — **estimates never enter the kernel**, however corroborated; a battle-tested model is still a model.

Everything else is membrane. The kernel is therefore *recomputed every sweep* — it can grow (verifications land) and shrink (disputes land). A shrinking kernel is honest signal, not regression.

### 2.4 MEMBRANE — the fuzzy frontier

```jsonc
"membrane": {
  "corroborated_soft": [ ... ],   // bucket=corroborated but cert<0.7 or ESTIMATE/PROXY-tagged
  "pending":           [ ... ],   // bucket=pending — fuzzy, awaiting battle
  "unverifiable":      [ ... ],   // bucket=unverifiable — soft spot, flagged
  "disputed":          [ ... ],   // bucket=disputed — membrane under attack; BOTH values carried
  "scars":             [ ... ],   // retracted facts (unverifiable + provenance-failure note,
                                  //   per SUBSTRATE gotcha 10) — demoted, visible, never deleted
  "open_questions":    [ ... ]    // known gaps + CANDIDATE EDGES not yet fact-backed (§2.7)
}
```

Each entry is a compiled fact row (`fact_id`, `predicate`, `value`, `bucket`, `certainty`, `battle_count`, `disputed_alternatives?`). The full facts-as-wrappers mapping that gives this block its meaning is §3.

### 2.5 FRAMES — observer-global-kernel relevance weights

```jsonc
"frames": {
  "time": 0.0, "space": 0.0, "knowledge": 0.0, "meaning": 0.0,
  "_estimate_note": "MANDATORY: these weights are AUTHORED RENDER ESTIMATES in [0,1], not measured quantities and not substrate facts. Disclose wherever rendered (UI_GUIDELINES §5)."
}
```

Same basis as SCHEMA_v2 (`{time, space, knowledge, meaning}` — the observer global kernels). The weights say *how strongly each kernel lights this entity up* for layout/prominence in group renders (§4). They are estimate-proxies under the standing proxy-disclosure discipline: the `_estimate_note` is mandatory, and any toy/viewer rendering them owes an adjacent disclosure.

### 2.6 LIFECYCLE — kind-appropriate, fact-backed

`lifecycle` is a compiled list of `{ event, when, fact_refs[] }` rows drawn from lifecycle predicates. Vocabulary per kind — **reuse the existing SUBSTRATE_SPEC §2.1 predicates wherever they exist; the rest are harvest extensions** (allowed by §2.1: "extend as needed, but prefer reuse"):

| kind | lifecycle predicates |
|---|---|
| person | `born`, `died`, `active_from`, `active_to` *(all existing)* |
| institution | `founded`, `dissolved` *(existing)* |
| object (generic) | `named` *(existing)*; `emerged`, `mass_adoption` *(new; dates may be partial-precision — put fuzziness in `notes` + lower certainty, not in invented precision)* |
| device-model | `announced`, `released`, `discontinued`, `superseded_when` *(new)* |
| ai-model | `announced`, `released`, `deprecated` *(new)*; `trained` *(new; value may be an interval object)* |
| compound | `first_synthesized`, `first_marketed`, `genericized` *(new; `genericized` is scope-suffixed like §2.2 when jurisdiction-relative)*; `named` *(existing)* |
| book | `written` *(new; interval ok)*, `published`, `adapted` *(new)* |

A lifecycle row with no fact is not drawn. No defaults, no placeholders (UI law §5.4: data-absent = draw nothing).

### 2.7 RELATIONS — every edge backed by substrate facts

```jsonc
"relations": [
  { "type": "instance-of", "target": "l0:smartphone", "fact_refs": ["l0-iphone-15-pro-r0001"],
    "bucket": "pending", "certainty": 0.8 }
]
```

**Initial controlled vocabulary** (subject —type→ target; extend via SWEEP_LOG proposal, propose-before-use):

| type | reading |
|---|---|
| `instance-of` / `subclass-of` | abstraction-ladder rungs (§2.2) |
| `brand-of` | branded specific → its generic (the ladder's second-kind echo: a brand rung is a specialization rung) |
| `part-of` | component → whole |
| `made-by` / `authored-by` | artifact → maker / work → author |
| `about` | work → its subject (a book *about* a person; alias `subject-of` read in reverse) |
| `conceptual-ancestor-of` | idea/person's named contribution → descendant lineage |
| `influenced` / `enabled` | weaker lineage / precondition edges |
| `available-on` | software/model → platform it runs on |
| `measures` / `treats` | instrument → measurand / compound → condition |
| `adapted-into` | work → derivative work |
| `named-after` | thing → eponym |
| `successor-of` | model/edition → its predecessor |

**Encoding in the substrate.** A relation is a fact in `facts/l0_catalog.relations.jsonl` with:
- `subject_id` = source slug, `fact_id` = `l0-<slug>-rNNNN` (the `r` namespace keeps relation ids disjoint from entity ids — same HAZARD logic as the existing `f-…-eNNNN` events convention),
- `predicate` = **`rel:<type>:<target-slug>`** (e.g. `rel:instance-of:smartphone`). The target is folded into the predicate so each *edge* is its own `(specimen, subject, predicate)` resolution group: multiple independent facts attesting the same edge then resolve to one best row (independent attestation = the edge's own battle-testing), while *distinct* edges of the same type never collapse onto one another. This is exactly the SUBSTRATE_SPEC §2.1 list-item disambiguation rule applied to edges.
- `value` = `{ "target": "<slug>", "note": "..." }`.

**Hard rule:** `relations[]` contains **only fact-backed edges**. An edge you believe in but cannot yet source goes in `membrane.open_questions` as a *candidate edge* with its proposed verification route — that is the membrane doing its job. Targets not yet in the catalog use `proposed:<slug>` and become next-sweep entity candidates (§7.2).

### 2.8 FRAME_LAYER — physical | latent | straddle (graded)

```jsonc
"frame_layer": { "layer": "straddle", "physical_membership": 0.6, "latent_membership": 0.7,
                 "_estimate_note": "authored analytic estimate, not a substrate fact" }
```

Reuses the SCHEMA_v2 D3 shape verbatim. The six samples deliberately spread across it: a person is physical (who also *carries* latent wrappers), a generic category is latent-leaning straddle, a specific handset is physical, a book straddles (text latent, codex physical), an AI model is latent with physical serving-infrastructure membership. Graded memberships, crisp as the special case (D5).

### 2.9 SUBSTRATE BINDING — the wrapper is a compiled view

```jsonc
"substrate_binding": {
  "specimen": "l0-catalog",
  "facts_files": ["../canonical_genealogy/substrate/facts/l0_catalog.entities.jsonl",
                  "../canonical_genealogy/substrate/facts/l0_catalog.relations.jsonl"],
  "verifications_file": "../canonical_genealogy/substrate/verifications/l0_catalog.jsonl",
  "compiled_from": "../canonical_genealogy/substrate/compiled/l0-catalog.compiled.json",
  "fact_id_namespaces": { "entities": "l0-<slug>-NNNN", "relations": "l0-<slug>-rNNNN" },
  "generated": "<ISO stamp>",
  "compiler": "tools/l0_compile_wrappers.py vX",
  "hand_assembled": false
}
```

Doctrine, in order of authority:
1. **Facts first.** Authoring order is: fetch source → append fact → recompile substrate → rebuild wrapper view. Never the reverse.
2. **The wrapper JSON is derived.** `l0_compile_wrappers.py` (sweep-1 build; stdlib-only, same constraint as `compile_substrate.py`) reads `compiled/l0-catalog.compiled.json` and partitions each subject's rows into kernel/membrane per §2.3–§2.4, assembles ladder + relations + lifecycle, and stamps `generated`. Until the builder lands, a wrapper view may be hand-assembled **only** with `"hand_assembled": true` and with every populated field still carrying real `fact_refs` — the builder, once built, must reproduce it byte-for-byte modulo `generated`.
3. **Same compiler, no fork.** `python compile_substrate.py` (run from `../canonical_genealogy/substrate/`) discovers `l0_catalog.*.jsonl` automatically (it compiles every `facts/*.jsonl`) and emits `compiled/l0-catalog.compiled.json` by the `specimen` field. **Expected, honest flag:** until a subject-index anchor exists, every l0 fact raises one non-fatal flag — `specimen 'l0-catalog' not found among ../specimens/*.json` — the same expected-flag pattern as `agnostic_framework.dev.jsonl`'s local-path sources. Documented = disclosed.
4. **Ratification-gated anchor (proposed, not built):** a minimal NEW file `../canonical_genealogy/specimens/l0_catalog.json` — `{ "specimen_id": "l0-catalog", "_doc": "subject-index ANCHOR for the L0 entity catalog; NOT a merge-event specimen", "entities": [{ "id": "<slug>", "name": "<canonical>" }] }` — would silence the flags *and* turn on exact `subject_id` validation (the compiler's `_walk_collect` picks up `id`/`name` keys). It touches nothing frozen, but it adds a 9th file to a directory the wiki documents as holding 8, so it waits for a Pav/Cowork nod, recorded in SWEEP_LOG when taken.

## 3. Facts are wrappers — the explicit mapping

Pav's convergence, made mechanical. **A fact is a micro-wrapper.** Its membrane hardness is not a metaphor on top of the substrate — it *is* the substrate's verification machinery, read in wrapper vocabulary:

| substrate concept | wrapper concept |
|---|---|
| `fact_id` | the micro-wrapper's identity |
| `value` + `source` + `retrieved_at` | the micro-wrapper's **kernel**: what it asserts and where it stood when caught |
| `certainty` (emit-time, never edited) | kernel sharpness as calibrated by the harvester — the membrane's *starting* thickness |
| verification **bucket** | the membrane's **state**: `pending` = fuzzy, unbattled; `corroborated` = **hardened** (survived an independent route); `disputed` = **under attack** — both values held at the membrane, neither deleted; `unverifiable` = a soft spot, flagged |
| each `corroborated` verification from an independent source | one **battle survived**; `battle_count` = number of independent corroborating routes — battle-tested = corroborated against independent routes, by definition |
| `disputed_alternatives` (compiler output, never dropped) | the attacker's value, held visibly at the membrane |
| retraction pattern (old fact + `unverifiable` verification w/ provenance-failure note + re-sourced new fact; SUBSTRATE gotcha 10) | a **demoted scar** — permanent, visible, never deleted (the claim-lifecycle "demoted, never killed" discipline at fact scale) |
| best-value resolution per `(specimen, subject, predicate)` group | which micro-wrapper currently *speaks for the slot*; the others remain in `provenance_refs` history |
| `when` / `source` / scope-suffixed predicates | the micro-wrapper's own frame anchors: time-frame / knowledge-frame / space-frame |

**An entity wrapper's membrane is therefore a population of micro-wrappers** at various hardening stages, and §2.3's kernel is just the sub-population whose membranes have fully hardened. Sweeps harden membranes (§7); they do not paint them.

**Recursion bottoms out at provenance** (disclosed design choice): a fact-micro-wrapper's own "facts" are its provenance fields; L0 does not recurse further.

### 3.1 Render mapping (LAW for any L0 toy/viewer, inherits UI_GUIDELINES.md whole)

- **corroborated** → hardened membrane segment (solid arc; `battle_count` on the hover chip),
- **pending** → fuzzy segment (translucent/dashed),
- **disputed** → segment under attack (warn-color accents; hover shows BOTH values + the verifier),
- **unverifiable** → soft spot (dim, flagged),
- **scar** → a visible notch, never removed,
- **open question / candidate edge** → labelled ghost (a gap drawn AS a gap; never a defaulted value).

**Membrane-hardness render proxy `l0-membrane-proxy-v0.1`** (versioned here per the PROXY_SPEC discipline; any toy embedding it must keep spec and code identical and bump the version on retune):

```
hardness h = B(bucket) * certainty
B: corroborated 1.0 | pending 0.55 | unverifiable 0.40 | disputed 0.25 | scar 0.10
ESTIMATE/PROXY-tagged facts additionally capped at h <= 0.5
```

`h` is a RENDER PROXY, not a measurement — the disclosure travels with every rendered hardness (UI law §5). **Falsification target:** if, across sweeps, high-`h` facts get disputed at a rate ≥ low-`h` facts (hardness fails to predict battle survival), the proxy is mis-weighted — retune and bump the version.

## 4. Group-frame configs — saved render configurations

A group-frame config is a first-class JSON object (one file per config in `group_configs/`) that the viewer/toys consume. It answers: *which wrappers, framed how, laid out how, at what LOD, for which observer.*

```jsonc
{
  "config_id": "grp-<slug>",
  "title": "",
  "wrappers": ["l0:<slug>", ...],
  "observer": {
    "kernel": ["time","space","knowledge","meaning"],   // subset: which global kernels the observer holds
    "frame_layer": "physical | latent | straddle",       // where the observer stands (D3 filter)
    "scope": "global | <jurisdiction/locale>"            // space-frame scope; drives §2.2 level_by_scope
  },
  "lod": {
    "depth": 0,                                          // relation hops beyond wrappers[] (0 = listed only;
                                                         //   1 pulls proposed: frontier in as ghosts)
    "membrane_detail": "kernel-only | kernel+membrane | full-fact",
                                                         // full-fact explodes each fact into its own
                                                         //   micro-wrapper glyph (§3 rendered literally)
    "abstraction_dial": { "<slug>": "generic|class|instance" }
                                                         // per-ladder rung selection — dialing = REFRAME (§2.2)
  },
  "layout": "timeline | constellation | abstraction-ladder",
  "edges": "all | fact-backed-only | [type, ...]",
  "options": { },                                        // layout-specific (below)
  "provenance_chips": true                               // fact/spec/ovr-style chips on hover (UI law §3.2)
}
```

**The three layouts:**

1. **`timeline`** — all wrappers' lifecycle rows on one shared time axis; the time-axis toy's calendar↔order blend (`lam`) and fisheye graduate here unchanged (`options: { lam, fisheye }`). Wrappers with no dated facts render as undated side-chips, not at an invented position.
2. **`constellation`** — force layout; node = wrapper (kernel disc + membrane ring of per-fact segments per §3.1); edge = relation (fact-backed solid; candidate-edge ghost-dashed only when `edges:"all"`). Observer kernel re-weights node prominence by `frames` weights — **disclosed as the estimate-proxy it is** (§2.5).
3. **`abstraction-ladder`** — vertical ladders, one per ladder-family present; the contextual-scale dial slides along generic ↔ class ↔ instance rungs; multiple ladders side-by-side expose the cross-kind echo (smartphone ladder beside aspirin ladder); `observer.scope` switches scope-suffixed levels (the genericide demonstration) — and renders the switch ONLY where scoped facts exist.

**Observer kernel = the same observer machinery** the genealogy viewer already has (observer picker, VIEWER_SPEC §9): which frame channels the observer holds + where they stand. Changing observer or scope re-renders identity and prominence — frame-relativity is the feature, not a bug.

**Three configs ship with sweep-1** (as files; sketched here as targets):

| config_id | wrappers | layout | the point |
|---|---|---|---|
| `grp-six-sample-constellation` | all six §5 samples | constellation, depth 1, kernel+membrane | the full interconnection web + proposed: frontier ghosts (Apple, Anthropic, Bayer, Hodges...) |
| `grp-turing-lineage-timeline` | alan-turing, turing-enigma-hodges, claude, iphone-15-pro | timeline | one lineage spine across person → book → ai-model → device, ~1912 to now |
| `grp-two-ladders` | smartphone, iphone-15-pro, acetylsalicylic-acid | abstraction-ladder, scope toggle global/US/DE | the contextual-scale dial in TWO kinds at once; level-by-scope live |

## 7. Sweep protocol — how sweep N+1 runs cold

The standing Sonnet-fleet pattern: each sweep adds entities, fills gaps, deepens verification, extends relations. A cold agent needs only the files below.

### 7.1 Read order (the onboarding contract)

1. `../canonical_genealogy/wiki/` — `data-layer.md`, `substrate.md`, `toys-specs.md`, `UI_GUIDELINES.md` (LAW for any UI work)
2. This spec + `wrapper.template.json`
3. `../canonical_genealogy/substrate/SUBSTRATE_SPEC.md` (fact/verification schemas, rubric)
4. `SWEEP_LOG.md` (last sweep's state, locked dials, proposed-vocabulary queue)
5. `../canonical_genealogy/substrate/compiled/l0-catalog.compiled.json` + `compiled/_summary.json` (current coverage/buckets)

### 7.2 The sweep loop (in this order)

1. **Harden** — verify standing `pending` facts: fetch an INDEPENDENT second source per fact, append verification records (`corroborated`/`disputed`/`unverifiable`) to `verifications/l0_catalog.jsonl`. This is membrane hardening — the highest-value move; do it before adding breadth.
2. **Fill** — work the membranes' `open_questions` and empty lifecycle/edge slots of EXISTING wrappers; convert candidate edges to fact-backed relations where a source attests them; emit scoped `abstraction_level:<scope>` facts where the record forces frame-relative levels.
3. **Extend** — promote `proposed:` targets to catalog entities (new slugs, new facts), starting from the standing frontier list (sweep-2 starts from the eight in §5). Each new wrapper's relations will mint the NEXT frontier.
4. **Recompile** — `python compile_substrate.py` from `../canonical_genealogy/substrate/` → expect `validation errors: 0`; review flags (the unknown-specimen flag per §2.9.3 is expected until the anchor lands).
5. **Rebuild views** — run `tools/l0_compile_wrappers.py` (or hand-assemble per §2.9.2 until it exists) → refresh `wrappers/*.wrapper.json`; refresh any `group_configs/` whose wrapper lists grew.
6. **Log** — append a dated section to `SWEEP_LOG.md`: entities added, facts emitted (id ranges), verifications by outcome, kernel growth/shrinkage per wrapper, disputes opened, scars added, frontier list for sweep N+2, and any PROPOSED vocabulary (kinds, relation types, predicates) awaiting next-sweep adoption.

### 7.3 Hard rules (the guards)

- **Namespaces / HAZARD:** entity facts `l0-<slug>-NNNN`, relation facts `l0-<slug>-rNNNN`; check the existing max per slug before emitting; never reuse an id across different `(specimen, subject_id, predicate)` groups — the compiler's HAZARD check is FATAL (exit 2) by design.
- **Append-only everywhere:** never edit an emitted fact/verification line; revise by appending (newer fact wins per resolution order); retract per the scar pattern (§3). `SWEEP_LOG.md` is append-only.
- **No fabrication:** real fetched URL or skip the fact. Leads in §5 are search hooks, not citable values.
- **Dial-lock per sweep (frame-lock discipline):** the classifier dials — kind vocabulary, relation vocabulary, kernel admission rule (§2.3), membrane proxy weights (§3.1) — are **locked for the duration of a sweep**. Changes are PROPOSED in the sweep log and apply from the NEXT sweep only (after a nod), so a sweep's results are auditable against fixed rules — the same frame-lock move that keeps a census falsifiable.
- **Agent stamp:** `agent: "l0-sweep-NN-<seat>"` on every fact; `verifier: "l0-sweep-NN-<seat>"` on every verification — and verification of a fact by the seat that emitted it does not count as independent.
- **Scope:** sweeps touch ONLY the §1.1 file map's new files. Ratified files, frozen specimens, Cowork's files, `frame_lock_data/`, existing fact files: never.

### 7.4 Sweep health readout (qualitative, no fabricated scores)

Each sweep log closes with: kernel-fact count vs membrane-fact count per wrapper (from the compile), dispute count, scar count, frontier size. The honest gauge is the **trajectory of hardening** (pending→corroborated conversions per sweep), not catalog size. A sweep that only verified and disputed — adding zero entities — can be the best sweep of the year.
