## §9 — Phase-1 architecture: the weighted-classifier wrapper-class database, the utility ranking, and the git-like submission pipeline (an agnostic canon render system)

> **Status:** Tier-3 **working artifact** per [cont 27 §2](../continuations/27.md) — a first-pass classification of *existing* canon into a new structure (a render). NOT new canon, NOT a promotion, NOT a build. Register: narrow-factual ([audit v08 §C7](../audits/v08.md)). This is Phase 1 of Pav's 2026-06-08 Latent Olympics steer: *collect + classify + lay out the framework's own wrapper classes* as a structured database whose classifiers carry **weights, not hard values**. It folds onto the [latent_olympics_DESIGN_SKETCH.md](latent_olympics_DESIGN_SKETCH.md) §2–§7 design; this section operationalizes the *internal* collect/classify step and the submission pipeline built to scale to the public/social layer later (the "runway / two birds").

### §9.1 — The weighted-classifier wrapper-class database schema

The unit of the database is a **wrapper-class record** — one row per construct the framework treats as a wrapper (the four/five civilization-scale construct studies already render this: marriage, religion, language, nation-state, internet — [cont 22 §7/§8](../continuations/22.md) — plus the framework's own internal wrapper classes: wrapper-overlap, A⁺/A⁻, canon-stack, L0, procedural lineage, phantom action-space, the adversarial function, etc.). Each record captures Pav's verbatim asks — *"how they overlap, how they came to be, who called it, what has risen to the top and what was demoted or became dormant till being resurrected/reinvented/getting stale, the local kernel canon of each one, their net product."* The fields:

- **`name` / `aka`** — canonical handle + the synonym set ("who called it," cross-field local names). This is the [§0 C0.1](adversarial_substrate_dynamics_BAR_A_SKETCH.md) "same shape named from scratch in N traditions" structure made a field.
- **`origin`** — how it came to be: the procedural-lineage trail ([cont 18 §1](../continuations/18.md): "rings on a tree," each layer the measurable-and-observable compile of the one beneath), with declared-parent stubs ([cont 25 §5](../continuations/25.md) hairy-sphere receptor-hooks).
- **`overlaps`** — typed edges to other wrapper classes (overlap / supersession / break-apart / dormant-resurrection), the [cont 25 §2](../continuations/25.md) lifecycle relation between two wrappers. This is what makes the DB a *graph*, not a list.
- **`status`** — lifecycle position on one soft axis: `risen` / `demoted` / `dormant` / `resurrected` / `stale` — directly Pav's vocabulary, mapped to [cont 20](../continuations/22.md) dormancy (preserved, wakeable) + [cont 25 §2](../continuations/25.md) branch states. Soft because a class can be simultaneously dormant-in-one-domain and risen-in-another (observer-relative).
- **`localKernelCanon`** — the keystone function(s) the class bottoms out into ([cont 32 Part B.2](../continuations/32.md): "L0's kernel canon = identifiable keystone functions"; [cont 22 §3](../continuations/22.md) Kanon-drill). Per cont 22 §7, the construct sits at a canon-*protocol* layer and the drill names where its actual Kanon lies below.
- **`netProduct`** — what the class actually outputs/compiles (the W_C it produces; the action-space it sustains). Pav's "net product."
- **`classifierWeights`** — the four soft scores `{spread, utility, legacy, rigor}`, each in **[0,1]**, from the [latent_olympics §2](latent_olympics_DESIGN_SKETCH.md) rating dimensions.
- **`utility`** — the structured sub-record (§9.2), since utility is now the PRIMARY ranking and decomposes.
- **`tier`** — the [cont 27 §2](../continuations/27.md) epistemic tier (1/2/3) the class currently holds.
- **`refs`** — file:section citations grounding every field (the provenance trail, §9.3).

**Why soft weights are the agnostic-correct choice (not a stylistic preference).** Pav: *"the classifiers have weights not hard values."* Three independent canon reasons force this:
1. **Observer-relativity.** Compiled canon is observer-relative output of an observer-relative compile loop ([cont 32 §F3 / Part B](../continuations/32.md); [cont 22 §6](../continuations/22.md)). A wrapper class's legacy/utility/rigor is *not* a property of the class alone — it is a property of the class *as rendered by an observer*. A hard categorical value would assert a view-from-nowhere the framework explicitly disclaims. A weight in [0,1] is honestly a *projection coefficient*, not a fact about the thing.
2. **The Pareto-not-scalar design ([§2](latent_olympics_DESIGN_SKETCH.md)).** Selection is the non-dominated set, never a weighted-sum scalar — a scalar "crowns a winner by fiat." Soft per-dimension weights feed a Pareto front; hard values collapse the front into a false total order. Keeping each dimension a soft coordinate is what *preserves* "no winner crowned by declaration, only by surviving development."
3. **Everything held-in-tension, nothing crowned.** Legacy and spread are deliberately *anti-correlated* ([§2](latent_olympics_DESIGN_SKETCH.md): the framework's attraction/repulsion pair on the conjecture pool); A⁺/A⁻ are charge-like dimensions in tension ([cont 13 §1](../continuations/13.md)); wrapper-overlap is "asymmetric flux, symmetry is the special case" ([cont 25 §12.4](../continuations/25.md)). A soft-weight vector *represents* tension (two dimensions can both be high); a hard label *resolves* it prematurely. The weights are the render's dials, re-settable per domain — which is exactly what makes the schema portable (§9.4).

### §9.2 — The utility function (the PRIMARY ranking — the most important part)

Pav's sharpening makes utility the **key ranking dimension**, and grounds it concretely:

> **utility(class) = w_a · actionSpaces + w_u · unifier + w_c · compression**, with `w_a + w_u + w_c = 1`, each leg a soft [0,1] score, the weights themselves soft and domain-tunable.

This **revises the earlier [§2 finding](latent_olympics_DESIGN_SKETCH.md)** that utility was the weakest dimension — "irreducibly human-judgment," "most diffuse," functioning only as a "zero-or-positive decoration gate." Grounded as action-space + unification + compression it is no longer a diffuse gate; it is a three-legged estimand, and **one leg is genuinely computable.** The measurable handle per leg:

- **(a) `actionSpaces` — new phantom/constructed action-spaces unlocked.** Ground: [cont 32 Part C](../continuations/32.md) phantom action-space (the **internal** sub-sense = possibility-paths the class's own speculation opens; the **attributed** sub-sense = action-space others now attribute through it) + the [§PS phantom-sense fold](adversarial_substrate_dynamics_BAR_A_SKETCH.md) (action-space as a *primitive* — a "field of latent affordance," the live set of moves/threats/affordances opened). *Handle:* count + quality of new live moves/affordances/questions the class opens that the prior vocabulary did **not** license — the [§2](latent_olympics_DESIGN_SKETCH.md) "enumerate what it licenses, subtract what the prior vocabulary licensed" remainder, now sharpened from "insight" to *opened action-space*. Higher when it opens a new constructed action-space (a new live move), per Pav. **Honest residual: judgment-dependent** — counting "new live moves" needs the AI/human panel; there is no closed-form.
- **(b) `unifier` — how many previously-separate things it bridges.** Ground: [cont 18 §0](../continuations/18.md) — the canon-promotion test is *"structural unification, not new decoration"* — and the [cont 25 §6/§7](../continuations/25.md) cross-substrate convergence concept (one dynamic independently formalized across N traditions; the framework's contribution is "the cross-tradition compile"). *Handle:* count of previously-separate wrapper classes / traditions the class bridges (its degree on the `overlaps` graph that resolve to a *single* compiled structure), weighted by whether the bridge passes the [cont 25 §6](../continuations/25.md) parents-produce-W_C structural test (a genuine unification) vs. a name-only family resemblance ([§0](adversarial_substrate_dynamics_BAR_A_SKETCH.md) is explicit that parallel naming ≠ tested convergence). **Honest residual: partly judgment-dependent** — the bridge-count is mechanical from the graph, but "is this one structure or a family resemblance" needs the panel.
- **(c) `compression` — latent/physical description-length reduction.** Ground: the [§IT information-theoretic spine](adversarial_substrate_dynamics_BAR_A_SKETCH.md) (KL = excess code-length, Cover & Thomas; MDL surrogate since Kolmogorov DL is uncomputable; the Landauer kT ln2 floor; the d′↔KL bridge for estimable cases) + the [cont 22 §2](../continuations/22.md) dual-kernel (physical-kernel **and** latent-kernel compression — Pav's "latent / physical compressor"). *Handle:* the reduction in description length (MDL / excess code-length in bits) of the corpus the class re-describes — how much shorter the canon gets once you adopt the class. **This is the genuinely quantifiable leg** — it is computable as a description-length delta (the [§IT C-IT-6](adversarial_substrate_dynamics_BAR_A_SKETCH.md) "portable metric panel" replaces eyeball judgments with bits, exact on instrumented cases, order-of-magnitude on soft ones). So `w_c · compression` is the part of the PRIMARY ranking that is **least judgment-dependent** — which is why it anchors the function.

**The honest shape of the revision (stated plainly):** the [§2](latent_olympics_DESIGN_SKETCH.md) worry was correct *about the old framing* (utility-as-vague-insight). Re-grounded, utility is more principled — but the principle is **uneven**: compression is computable (MDL), unification is semi-computable (graph degree + a judged structural test), action-space-unlocking remains a panel judgment. So utility is *not* fully automatable; it is **one computable leg carrying two judged legs**, and the weights `w_a, w_u, w_c` are soft per-event dials (a math/physics event leans `w_c`; an open-problem-reframing event leans `w_a`). This keeps the [§2 computability-split finding](latent_olympics_DESIGN_SKETCH.md) intact (human-judgment system with computational assists, not an automated leaderboard) while moving utility from "weakest/most diffuse" to "primary, one-third computable."

### §9.3 — The git-like submission pipeline (Pav: "almost like git")

The pipeline is built in Phase 1 for **internal** classification (the council submits wrapper-class records) but is the **same object** that scales to the public/social version later — that is the "runway / two birds." Four stages, each folded onto framework canon:

1. **SUBMIT (PR-like).** A wrapper-class record (or a new conjecture) is submitted with a **declared provenance trail** — the [§5](latent_olympics_DESIGN_SKETCH.md) requirement: declare (a) the tradition it descends from, (b) parent records by id (the [cont 25 §5](../continuations/25.md) stubs it attaches to), (c) the canon/established theory it builds on ([cont 22 §7](../continuations/22.md) drill). "Stop honestly where the drill stops" is legible and rate-able. *Folds onto:* [cont 18](../continuations/18.md) procedural lineage (the submission **is** a new ring declaring its inner rings) + [cont 27 §2](../continuations/27.md) tier-tagged entry.
2. **EVALUATE — AI panel of cross-domain experts.** A panel scores the record's `classifierWeights` and `utility` legs. The compression leg is computed (MDL); the unifier and action-space legs are the panel's judged scores (the §9.2 residual). *Folds onto:* the [§2.4 split-custody](latent_olympics_DESIGN_SKETCH.md) requirement (ranking-compute / category-definition / legacy-scoring under separate change-logs) + the [§7.1 measuring-ruler](latent_olympics_DESIGN_SKETCH.md) governance anchor (established science certifies legible positioning; the panel is the irreducible human-judgment core [§2](latent_olympics_DESIGN_SKETCH.md) names as unbuildable-away). Plural/forkable weightings ([§2.1](latent_olympics_DESIGN_SKETCH.md), like the [cont 25 §10](../continuations/25.md) mapping-toggle) mean "the panel" is not a single Schelling point.
3. **ISSUES / POKE-HOLES (adversarial challenge round).** Anyone can file an issue against a record or "poke holes in other models" (Pav) — challenge a declared parent edge (provenance laundering, [§5](latent_olympics_DESIGN_SKETCH.md)), a rendered-but-not-actual discipline ([§2.3 bad-faith rendering](latent_olympics_DESIGN_SKETCH.md)), or an inflated utility leg. *Folds onto:* the [§4 anti-gaming taxonomy](latent_olympics_DESIGN_SKETCH.md) (the six sub-primitives run as the pre-mortem) **and** the [cont 13 §1](../continuations/13.md) A⁺/A⁻ charge algebra — an issue is an **A⁻ (prune-vector) on a submitted A⁺ (candidate)**; "productive when generative (exposes weakness so it can be refined)," and [cont 15](../continuations/13.md) makes A⁻ the *primary* discipline. The challenge round is also where the [cont 13](../continuations/13.md) finite A⁻ budget is the resource a flooder targets ([§2.2](latent_olympics_DESIGN_SKETCH.md)) — so issues are rate-limited and lineage-weighted.
4. **APPEAL-WITH-NEW-EVIDENCE (re-open).** A challenged record can be re-opened with new evidence — the lineage *grows* (a new drill-edge, a landed prediction), and its scores re-compute. *Folds onto:* the [§5 earnable-legacy](latent_olympics_DESIGN_SKETCH.md) mechanism (a low-legacy "dream" earns legacy by new measurable connections, not endorsement) + [cont 27 §3](../continuations/27.md) graduation/pruning (appeal = a graduation attempt; failed appeal = demotion *on its own terms*; backward movement is first-class, [§3](latent_olympics_DESIGN_SKETCH.md)).

This is git-shaped end to end (submit → review → issues → appeal/re-open), and the [cont 25 §6 model-merging convergence](../continuations/25.md) note is apt: the framework already recognizes git-like timestamped provenance as a wrapper-overlap substrate. The internal pipeline and the public pipeline are **one schema, two intake policies** — internal = closed submission ([§6.3](latent_olympics_DESIGN_SKETCH.md)); public = the [§7.2](latent_olympics_DESIGN_SKETCH.md) exogenous-input layer added later. The flooding/governance attacks ([§4 §2.1/§2.2](latent_olympics_DESIGN_SKETCH.md)) are out-of-scope **by construction** in Phase 1 (no public intake to capture) and are the gated, deferred surface for the social phase.

### §9.4 — The agnostic-canon-render-system framing + portability, and the phase plan

**What the artifact *is*.** The schema + pipeline is a **render system**: it takes existing canon (the framework's own wrapper classes) and renders it into a structured, weighted, browsable, challengeable database. It is **domain-agnostic** — nothing in the schema names the framework specifically; the fields (origin/overlaps/status/localKernelCanon/netProduct/weights/utility) are the [cont 25 §12.6](../continuations/25.md) user-facing track (L0 / fields / hairy-spheres / lineage) made tabular. Pav: *"an agnostic canon render system that we can take across to other domains like language of civilisation."*

**Portability is already demonstrated, not just asserted.** The framework's own artifacts are civilization-scale wrapper classes it *already* renders: marriage, religion, nation-state, language, internet are the [cont 22 §7/§8](../continuations/22.md) construct studies — each has an origin (procedural lineage), overlaps (e.g., Japanese religion = Shinto + Buddhism + Catholicism syncretic, [cont 25 §12.3](../continuations/25.md)), a status (risen/dormant/resurrected), a local kernel canon (drilled below the social-protocol layer), and a net product. Loading those five into the schema *is* the Phase-1 cross-domain proof that the render travels to "the language of civilization." The [cont 22 §12.x](../continuations/22.md) Π_L cross-observer-class projection is the formal warrant that the same substrate-event renders into different canon under different domains — i.e., the schema is observer-class-portable by construction.

**The phase plan (Pav: "the project will have phases"):**
- **Phase 1 (this) — collect + classify + lay out.** Build the weighted-classifier wrapper-class DB and the git-like submission pipeline, internally. Populate it with the framework's own wrapper classes (internal primitives + the five civilization-scale construct studies). Deliverable: the schema (§9.1), the utility function (§9.2), the pipeline (§9.3), and a first-pass populated record set. This discharges the [§6.3 internal-v0](latent_olympics_DESIGN_SKETCH.md) value (a non-reflexive classify run on real canon) **without** exposing the rating function to public capture.
- **Later phases — the public competition + reservoir readout + cross-domain render.** Add the public intake (the [§7.2](latent_olympics_DESIGN_SKETCH.md) exogenous-input layer — the "squeeze when it goes public"), run the [§7.2](latent_olympics_DESIGN_SKETCH.md) pre-registered baseline-beating reservoir readout that de-vestigializes the public hook, and take the render across to other domains. **Social comes later; the pipeline is the runway** — built once, internally, on a schema designed to scale to the social version, so the two birds (internal classification artifact + scalable public submission infrastructure) are hit with one stone.

**Carry-forward / honest gates (unchanged from the design sketch, restated so Phase 1 doesn't over-claim):** the public layer still sits on the [§7.1](latent_olympics_DESIGN_SKETCH.md) governance residual (the reflexive gap is *relocated* to "capture the projection onto the canon," not closed — [audit v09 §5.5](../audits/v09_DRAFT.md)); the soft band Pav most wants ("search under rocks") has only the weaker time-based audit-cadence ruler, not the faction-proof established-science ruler ([§7.1](latent_olympics_DESIGN_SKETCH.md)(i)); and the reservoir is coupled to the contested rating function ([§7.2](latent_olympics_DESIGN_SKETCH.md), partial decouple = hold the rating function *out* of the reservoir state). Phase 1 is defensible precisely because it is the **internal** step that needs none of those resolved; they gate the **later** social phases.
