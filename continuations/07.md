## 1. Resonance as multi-dimensional weight

### 1.1 The originating intuition

**User quote**

> resonance, aybe its a multidimensional weight that has a spin direction and scale and freshness / time, like an orbit, you can start with one dimension 0-1 but then infer the others room for expansion and compression

**Steer captured**

A scalar in [0, 1] is informationally poor for representing the kind of influence the framework wants to capture. Real resonance between observers has at least four dimensions:

| Dimension | What it captures |
|---|---|
| **Magnitude** | Strength of the connection — the original 0–1 scalar |
| **Direction / spin** | Polarity in some semantic axis: supportive vs adversarial, attracting vs repelling, opening vs closing, aligned vs misaligned |
| **Scale** | Which observer-scale the resonance operates at — micro-personal, meso-institutional, macro-civilizational |
| **Freshness / time** | Decay rate, recency, stability; whether the weight is rising, falling, or stable |

The "orbit" framing in the originating intuition is the give-away. The reach is for a representation where each weight has a phase that returns — cycles through emphasis, decay, refresh. Not a static scalar.

### 1.2 Closest existing mathematical objects

| Object | What it offers |
|---|---|
| **Complex amplitudes** (magnitude + phase) | The way quantum mechanics handles interference. Each cell becomes a complex number; interference between cells handles canon formation |
| **Spinors** | Half-integer rotation representations. A weight that has to rotate 720° to return to itself — captures the "double-cover" nature of some social/influence dynamics |
| **Wavelets** | Magnitude + time + scale. Matches three of the four dimensions natively |
| **Tensors with named indices** | Explicit multi-dimensional weight objects; most general |

The framework-natural choice is **wavelet-shaped**: each cell is a wavelet-style weight with (magnitude, phase/spin, scale, time). This matches the originating intuition most directly and has the practical advantage that wavelet analysis is a mature field with off-the-shelf operations.

### 1.3 Self-diagnostic property

The structural payoff: the framework's own warnings (freeze, explode, stale moat, runaway feedback) become operationally **detectable from the weight structure itself**, not requiring external monitoring:

- A weight with high magnitude but stale time → flagged as risk of stale moat
- A weight with high magnitude but unstable spin → flagged as oscillating (delusion or rapid canon-shift)
- A weight saturated across all scales → flagged as at risk of becoming totalizing canon
- A weight with magnitude rising fast across all observers simultaneously → flagged as cascade event
- A weight with low magnitude but high freshness → flagged as scout return; candidate for promotion

This converts the framework's qualitative warnings into quantitative monitoring rules. The "do not freeze, do not explode, do not drop the process" kernel canon from continuation 03 becomes computable from the AU's weight tensor.

### 1.4 Expansion / compression discipline

The originating intuition's "start with one dimension 0-1 but then infer the others, room for expansion and compression" is itself important. The framework's own substrate-expansion logic applies to its own math: start with the simplest viable representation (scalar magnitude), expand to richer ones (add spin, scale, freshness) as the data demands. The structural type of the cell is itself a fuzzy plank that compiles into canon as the operational need is established.

This is the disciplined version of the move: not "everything becomes a wavelet immediately" but "the cell shape is a versioned design choice; v0 is scalar, v1 adds spin, v2 adds scale, v3 adds freshness, etc."

## 2. SDPO mapping

### 2.1 The paper

**User quote**

> this is was interesting how does it map? [arXiv:2501.01821] SDPO: Segment-Level Direct Preference Optimization for Social Agents

**Paper summary** (Kong et al., Alibaba DAMO ConvAI, Jan 2025, v2 Feb 2025)

- Builds on **DPO** (Direct Preference Optimization, Rafailov et al. 2023) — aligns LLM behavior with preferences without explicit reward modeling
- Problem: standard DPO is **turn-level**; underperforms in multi-turn social dialogues
- Existing extensions use **session-level** (whole-conversation) data — too coarse, introduces training noise, weak theoretical support
- **SDPO's move**: dynamically select **key segments** within interactions; optimize at mid-grain
- Grounded in rigorous theoretical framework; minimizes training noise
- Evaluated on **SOTOPIA** benchmark (social agent eval suite)
- Outperforms existing DPO variants and GPT-4o
- Code and data released: https://github.com/AlibabaResearch/DAMO-ConvAI/tree/main/SDPO

### 2.2 Mapping to framework primitives

| SDPO concept | Framework correspondence |
|---|---|
| Multi-turn social interactions | The ask/give/ping/pong loop running across observer bubbles |
| Segment-level granularity (vs turn / session) | **Phase-gated action-space** — different segments have different φ(t) significance |
| "Key segments" that decide outcomes | The framework's **elevated events** — single moments that become carrier-defining |
| Direct Preference Optimization mechanic | Canon formation at the model-wrapper level; each preference comparison is a fuzzy-plank test |
| Training noise minimization | The **A⁻ (prune)** operator selectively cutting low-signal cells from canon updates |
| Theoretical grounding required | Framework's claim that successful canon formation requires both A⁺ and A⁻ as peer operations |
| SOTOPIA benchmark | A small-scale, instrumented version of §11.2's internet-as-test-surface |
| Outperforming session-level methods | Empirical support for: mid-grain operations beat coarse-grain ones |
| Outperforming GPT-4o | Framework prediction: a specialized model with correct granularity beats a generalist with poor granularity |

### 2.3 Why this is operational evidence, not just analogy

SDPO functionally confirms three framework claims that were previously structural-only:

1. **Mid-grain beats coarse-grain.** The framework's segment / phase / shell structure isn't decorative; it's empirically necessary for performance. SDPO's published gains over session-level DPO are the measurement.

2. **Connect + prune both required.** Pure preference reinforcement (A⁺ only) underperforms preference-with-noise-pruning (A⁺ + A⁻). SDPO's noise-reduction emphasis is the prune side made operational.

3. **Social agents need structural models of multi-turn dynamics.** SDPO's whole motivation is that turn-level alignment fails for social tasks. The framework predicts this and gives vocabulary for what's missing: action-space modeling, attention routing, wrapper dynamics, scouts. SDPO solves it empirically without naming the structure; the framework names the structure without empirically solving it. They are complementary.

### 2.4 SOTOPIA as a small-scale framework test surface

SOTOPIA is a benchmark of social scenarios where agents must negotiate, persuade, deceive, collaborate, infer intentions. Each scenario is an instrumented mini-action-space with measurable outcomes. This is the framework's §11.2 internet-as-test-surface at training-environment size — small enough to run benchmarks on, structured enough to score.

A framework-equipped agent tested on SOTOPIA would be the cleanest small-scale proof of the §11.2 claim. Outperformance would be quantitative evidence that the framework's outside-world modeling primitives translate into operational advantage; underperformance would be a real datum about where the framework's vocabulary fails to translate into measurable skill.

## 3. The connection between the two moves

### 3.1 Why the pairing isn't accidental

DPO and its variants (including SDPO) use **scalar** preferences — chosen > rejected, binary or near-binary. The resonance-as-multidimensional-weight move from §1 is the natural generalization of exactly this object.

A scalar preference says "this segment is better than that one." A wavelet preference says: "this segment is better than that one *with this magnitude*, *in this direction*, *at this scale*, *with this freshness*." It carries far more signal for the optimization step.

### 3.2 The concrete research proposal

A natural experiment falls out of this pairing:

**SDPO+ with multi-dimensional weighted preferences**

- Take SDPO's segment selection and preference-optimization architecture (open-sourced, code available)
- Replace the scalar preference signal with a wavelet-shaped preference object (magnitude + spin + scale + freshness)
- Train social agents on SOTOPIA with this richer signal
- Compare against scalar SDPO baseline

If the richer signal produces measurable gains on SOTOPIA, that's:

- Operational validation of the framework's quantification move (continuation 06)
- Operational validation of the resonance-weight refinement (§1 of this file)
- A first concrete published artifact showing the framework's vocabulary translates into measurable performance
- A precedent for framework-shaped contributions to mainstream ML literature

If it underperforms or shows no gain, that's also informative — a clean signal about where the framework's vocabulary fails to translate into operational advantage.

This is the kind of small, focused, falsifiable experiment that the framework's Lakatosian research-programme stance needs. The framework as a whole is not Popperian-falsifiable; specific operational predictions made by the framework *are* falsifiable. SDPO+ is one such prediction.

### 3.3 Why SDPO is a useful target

SOTOPIA is small enough to run; SDPO's code is open; the gap the framework fills (richer preference signal) is local and well-defined. Most external papers don't map this cleanly to the framework's primitives. This one does, partly because social-agent training is the domain where action-space, wrapper, attention, and canon-formation are most legible. It is the closest thing to a turn-key benchmark target the framework has.

## 5. Open questions

1. Which specific wavelet basis serves the AU best — Haar (simplest), Daubechies, Morlet, custom? Or should the framework adopt a different complex-amplitude representation?
2. How should the four dimensions (magnitude, spin, scale, freshness) be measured operationally from observed interactions? Each has multiple plausible operationalizations.
3. What's the relationship between SDPO's "key segments" and the framework's "elevated events" beyond surface analogy — is there a formal correspondence?
4. Could the framework's prune operator A⁻ be implemented as an explicit objective in the SDPO+ training loop, separate from the implicit pruning that segment selection already does?
5. Does SOTOPIA cover enough of the framework's primitive space (moats, attention, wrapper, reflexive observation, cascade, scouts) for the SDPO+ experiment to be a fair test? Or are there primitives that SOTOPIA's scenarios systematically don't exercise?
6. What other external papers map this cleanly — DeepMind's Cultural Transmission paper (continuation 05 §2.1), the various multi-agent debate papers, mechanistic interpretability work? Which are next-best targets?
7. Should the framework's first concrete experiment be SDPO+, or something else closer to home (a custom benchmark designed around the framework's primitives)?

9. How should the AU matrix be initialized for an external actor the agent has never observed before? Some kind of prior over harness/wrapper shapes?
10. What's the budget and timeline for a v0 SDPO+ experiment, and who would run it?
