## §2 Important refinements to existing framework framing

**§2.1 The four BES operators don't all instantiate parents-produce-W_C.** Per subagent's tightness ratings:

| Operator | Framework primitive | Tightness |
|---|---|---|
| Combination | parents-produce-W_C | 5/5 |
| Crossover | creole-genesis pattern at trajectory level | 4/5 |
| Translocation | procedural lineage transfer (cont 18) | 4/5 |
| Deletion | **NOT canon dormancy** — A⁻ pruning | 3/5 (remap) |
| Expansion | baseline A⁺ single-trajectory generation | not a wrapper-overlap op |

Only the three two-parent operators instantiate parents-produce-W_C. Deletion gets remapped to A⁻ discipline. Expansion is not a wrapper-overlap operator at all (it's pure A⁺ generation). This refinement actually strengthens the framework — BES becomes a worked example of three distinct framework primitives applied to one substrate, not one undifferentiated mash.

**§2.2 BES backward goal-tree ≠ cont 27 §2 tier-tagging.** Similar shape, different semantics. BES decomposes by task-granularity; cont 27 decomposes by epistemic-certainty. Subagent rates this 3/5 — record as candidate, not canon. The framework should not claim cont 27's tier-tagging is the same primitive as BES backward search.

**§2.3 The dense-vs-sparse-feedback claim IS tight (5/5).** BES §1 motivation — *"two fundamental limitations: (1) The verification signal to guide the search is sparse… (2) They struggle to generate candidates beyond the model's own distribution"* — is structurally identical to cont 13's A⁻-promoted-to-primary discipline. The framework gains formal mathematical grounding for the A⁻-primacy claim it currently lacks.

## §3 The fruit-as-analogy clarification

In conversation, an analogy surfaced: cross-substrate convergence as **fruits from different trees containing the same seed**. Tree = substrate + observer-wrapper compiling it. Fruit = transmissible compressed artifact (paper, equation, algorithm). Seed = structural pattern (parents-produce-W_C). Consumption + dispersal = receiving observer reads it. Germination = receiver compiles seed in their own substrate. New tree = new instantiation of same structural pattern at new substrate.

**Pav's clarification: this is an analogy, narrow but easy to digest. NOT canon. NOT a primitive.** Per cont 27 §2 discipline, analogies are illustrative pedagogical aids, not load-bearing structural commitments. The fruit-decomposition exercise (last response in this conversation) showed the analogy decomposes almost entirely into the framework's existing canon (carrier-before-canon, supersede branch, wrapper-overlap, bridge mode, A⁻ at consumer scale, kernel-meets-new-L0) — it's an assembly, not a new primitive.

**What the fruit analogy IS useful for:**
- Outreach (it's legible to non-framework-fluent readers immediately)
- Teaching (it makes cross-substrate-transmission tangible)
- A way to talk about the framework with someone who doesn't have the vocabulary yet

**What the fruit analogy is NOT:**
- A canon entry
- A candidate primitive
- A formal claim in framework discipline

The fruit-decomposition exercise did surface two genuinely-new Tier 3 candidate refinements that the existing canon doesn't capture cleanly:

- **Seed-hardness (Tier 3 candidate):** structural compression as A⁻-resistance during cross-substrate transmission. Different from dormancy (voluntary expression-reduction). Different from break (canon discarding). Closer to: structural-density-as-A⁻-resistance. Held as candidate.
- **Maturation-gated supersede (Tier 3 candidate):** compile loop with internal A⁻ check producing detachment-readiness as a terminal state, then auto-triggering supersede-branch. Different from cont 25's pressure-driven or contact-driven supersede triggers. Held as candidate.

These are minor refinements, not load-bearing additions. They're queued for potential promotion if downstream worked examples surface, otherwise they stay as low-priority Tier 3.
