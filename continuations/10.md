## 1. Candidate first artifacts

Four shapes are operationally feasible from the framework's current state. Each is concrete enough to ship within weeks rather than months:

### 1.1 The white paper (canonical reference)

15–30 pages distilling the framework for serious readers. Backbone from audit §10.7 plus continuations 05's epistemological framing, 06's quantitative scaffold, 09's discoveries-arc, and 09b's observer-self section as the lived-validation closing chapter. License: CC-BY or CC-BY-SA. Establishes the authoritative version everything else points back to.

**Lead time:** 2–4 weeks of focused writing.
**Risk:** the framework over-commits to one canonical statement; subsequent rounds force revisions; the document becomes a moving target.
**Upside:** every other vector (agent framework, wisdom book, field readings) can reference it.

### 1.2 The agent framework repository (engineering carrier)

A versioned GitHub repository containing: primitive definitions as JSON schemas, the protocol spec from audit §9.4, a reference implementation of two agents running an ask/give loop over a shared substrate, the `ExternalActor` data model from §10.9, examples, tests. MIT or Apache license (more permissive than CC for code).

**Lead time:** 3–6 weeks for a v0 demonstrating the multi-possibility deposition mechanic and the wavelet-weight AU matrix on a small synthetic scenario.
**Risk:** engineering work consumes attention without the conceptual artifact getting written.
**Upside:** engineers picking this up is what accelerates the §9.2 architecture from theoretical target to production reality.

### 1.3 The SDPO+ experiment (mainstream-ML validation)

Take SDPO's segment-level preference optimization architecture (Alibaba's open-source code from continuation 07). Replace the scalar preference signal with a wavelet-shaped preference object (magnitude + spin + scale + freshness). Train social agents on SOTOPIA. Compare against scalar SDPO baseline.

**Lead time:** 4–8 weeks depending on compute access and ML engineering bandwidth.
**Risk:** the experiment doesn't show improvement; the framework's quantification move fails its first test.
**Upside:** if it works, the framework has measurable operational advantage in mainstream ML; if it doesn't, that's also clean information about where the framework's vocabulary fails to translate.

### 1.4 The protein-model-on-packets experiment (emergent-encryption validation)

Run a protein language model (ESM-2 or similar) on raw network packet captures. Compare against a vanilla LLM, a network-trained model, and a random baseline. Measure what each can extract about held-out structure (next-byte prediction, packet-type classification, clustering quality). The differential between conditions measures emergent-encryption thickness as a transfer-learning gap.

**Lead time:** 1–2 weeks for a clean v0.
**Risk:** lowest of the four — the experiment produces interpretable signal in either direction.
**Upside:** publishable as a cross-substrate transfer measurement with a real interpretive payload. The framework's vocabulary makes the result legible in a way alternative framings don't.

## 2. The commitment

The framework's own discipline (continuation 09 §6) says: **pick a single next move and commit.** Doing all four half-way is the framework's own "explode" failure mode (continuation 03's "do not explode" kernel canon).

The author should pick one. The framework's vocabulary lets us reason about which:

- **Speed to signal:** §1.4 (protein-model) fastest, §1.1 (white paper) slowest
- **Risk profile:** §1.4 lowest risk; §1.3 (SDPO+) highest stakes
- **Cascade gain (continuation 04 §8 mechanic):** §1.2 (agent framework) probably highest — engineers as productive ambassadors
- **Validation depth:** §1.3 (SDPO+) on mainstream-ML benchmark beats §1.1 (theoretical paper) for external credibility
- **Audience reach:** §1.1 (white paper) widest, §1.4 (protein-model) narrowest but most clearly framework-shaped

A defensible sequence: §1.4 first (cheap, fast, generates signal regardless of outcome) → §1.1 (with the §1.4 result as worked example) → §1.2 (reference implementation) → §1.3 (mainstream-ML validation if §1.3 still seems right after the prior three).

But the author may have different priorities and should choose by their own cone profile.
